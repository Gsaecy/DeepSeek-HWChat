# HWChat

[English](README.md) · 中文

HWChat 是面向 VS Code 的本地优先编码 Agent 扩展。

HWChat 是一个在 VS Code 内直接编码的 DeepSeek / OpenAI 兼容 Agent 扩展。它提供简洁的聊天与设置界面、原生流式 tool calling、本地 Skill、文件附件、权限预设、带归档快照的任务清单、标注「在哪里运行 / 用什么工具」的终端命令、归档历史和可恢复的分片存储。聊天固定在 VS Code 右侧辅助侧边栏，不会再占用编辑器标签页。

![HWChat 聊天面板：左侧会话列表与新建对话](https://raw.githubusercontent.com/Gsaecy/DeepSeek-HWChat/main/docs/screenshots/chat-panel.png)

延伸阅读：[HWChat 推荐文章](docs/article-zh.md)（约 3500 字，讲设计取舍：为什么解绑模型、四档权限怎么划、Skill 为什么要路由加载）。

## 编码 Agent

- `Agent`：读取和搜索项目、检查诊断、创建/修改/移动/删除文件、运行命令，并把工具结果继续回传模型完成多轮任务。
- `Plan`：只开放只读工具，用于分析代码和制定方案，不修改工作区。
- `Chat`：不开放工作区工具，仅使用对话和明确添加的上下文。
- 工作模式以「对话工具条的下拉」和「设置里的默认模式」为准：新对话用 `hwchat.defaultMode`，在工具条里切换会立刻写进当前对话存档，之后每次请求都按它执行；每次请求还会把当前模式明确写进系统提示词（并声明以本轮为准），所以跨模式续聊不会沿用上一个模式的假设。工具清单、权限拦截和提示词三处用的是同一个模式值。
- 原生识别 VS Code 的单根和多根工作区，可直接列出工作区根目录、浏览目录、读取文件，并通过 `open_file` 在编辑器中打开文件，不再绕行终端、`code` CLI 或其它扩展工具。由 VS Code 扩展提供的桥接工具与原生工具受同一套路径隔离约束，其说明里会标注文件类参数必须使用工作区内绝对路径。
- 在受信任工作区和当前权限预设允许时，Agent 可自行执行工作区内命令。终端命令按风险分成三档：只读命令（`ls`、`git status`、`grep` 等）、正常命令（安装、构建、提交等）和危险命令（提权、破坏性删除、磁盘擦写、强制推送、把网络脚本管道给 shell 等）。`每次询问` 全部确认且危险命令直接拒绝；`风险操作询问` / `Autopilot` 自动执行只读与正常命令、危险命令逐次确认；`完全访问` 连危险命令也自动执行，但读取敏感文件时仍逐次确认。未受信任工作区和工作区外路径隔离始终有效。命令里 `sed` / `grep` 的模式或脚本参数（如 `sed -n '/a/,/^b/p'`）按模式处理，不会被误判成越界路径；真正的文件参数仍然逐个校验，直接指向文件系统根的写法（如 `rm -rf /`）同样会被拒绝。
- 命令执行期间会持续告诉你它还在动：步骤卡片按秒刷新「已运行 12.3 秒」，不再只在结束后才显示耗时。如果一条命令 **30 秒没有任何输出**，卡片会变成警示色、正文写明「已 X 秒无输出，可能在等终端输入」，并弹一条通知，同时说明超时上限。那个秒数**每 10 秒刷新一次**，不再定格在 30——左边「已运行」在跳、右边「已 30 秒」不动，看着像界面又卡了；而通知本身只弹一次，保持它是提醒而不是噪音。通知的显示时长按文字量算——中文停滞提醒现在约 9 秒（原来一律 4.2 秒，六十多个汉字根本读不完），短提示仍维持 4 秒；点一下通知可以立刻收起。因为卡住的命令和正常运行的命令，本来在界面上长得一模一样。超时会**按进程组**终止整棵进程树：只杀 shell 时，`cargo`、`qlmanage` 这类孙进程会活下来并继续占着输出管道，让这次调用永久挂起（真实发生过：卡片停在「准备运行命令」半小时，而测试进程只用了 0.01 秒 CPU）。结算有三重兜底——正常退出、退出后 1.5 秒宽限、SIGKILL 后 3 秒硬结算，任何一条都能保证调用一定返回结果。另外 HWChat **无法把终端交给你输入**：`sudo`、`ssh` 这类需要密码的命令会直接读到 EOF 并失败，请改用无交互方式。单条命令的执行上限取「设置值」与「工具请求值」中较小的一个，默认 120 秒（可在设置里调到 5–900 秒），所以请求里写一个更大的值并不会延长上限。
- 每个执行步骤默认折叠，只显示结果摘要；展开后可查看工具输入、输出、审批状态、耗时和涉及文件。展开/收起状态由用户决定：流式输出期间列表重新渲染也不会再自动收起，点开保持展开，再点一次才收起。**流式输出期间不会重建步骤节点**：锚点落在「正文还没写到」的位置时，这一步只是被**临时**贴在末尾，而这个临时位置会随正文每长一个字而变——把它当成结构变化，就会每帧重排整条消息，后果是悬停高亮丢失（CSS `:hover` 只在元素仍是指向目标期间生效，节点被换掉就没了）和点击被吞（按下与松开之间节点被换掉时，click 会派发到最近共同祖先——实测更糟，**根本不派发**）。所以签名里把这类分组统一抹成 `pending`，只有真实变化（工具出现/状态改变，或正文终于写到那个锚点）才重排（回归测试见 `src/test/toolGroupStability.test.ts`）。**点击折叠标题另有 `pointerup` 兜底**：松开时如果发现按下那个 summary 已不在文档里，就按稳定的 `data-detail-key` 重新找到同一步并切换 `open`——与 HTML 规范给 `summary` 定义的 activation 等价。在按下矩形之外松手不生效，节点还在时一律交给浏览器，所以正常点击不会双触发。
- 可从聊天输入区添加多个文件，也可在资源管理器右键选择“HWChat: 添加文件到对话”。文件内容不会发送给 Webview，只在扩展宿主中按需加入 API 请求。
- 支持多个 OpenAI 兼容 API 配置档，每个配置档可独立保存地址、API Key、模型列表和请求头，并在对话标题下方的控件行即时切换。
- 模型选择不依赖 Copilot 或其它扩展注册的模型。HWChat 会直接调用当前 API 的 `/models` 接口读取可用细分模型和展示名称，过滤接口标记为停用、过期或不可用的模型，并记住用户手动排除的模型；DeepSeek 官网接口在首次刷新前以 `deepseek-flash` 和 `deepseek-v4-pro` 作为离线兜底。
- 思考层级**按所调用模型自己声明的档位**渲染，与 Copilot 一致：DeepSeek 官方 `/models` 在 `effort.supported_levels` 里声明 `low`/`high`/`max`（`none` 按官方定义不在这个列表里，因为它是「关闭思考」），界面因此显示 **默认（模型官方） / 无 / 低 / 高 / 最大** 五档。新对话默认「默认（模型官方）」——不发送 `reasoning_effort` 与 `thinking`，由服务端按该模型自己的官方默认值处理。选「无」= 关闭思考，实际发送 `thinking: {type:'disabled'}` 与 `reasoning_effort: 'none'`。其他 OpenAI 兼容接口没有 `max` 这一档，会折算成它的最高档 `high`。档位只在当前模型声明可调时开放；不支持、固定思考或能力未知的模型不会伪装成可调节。**模型发现（`/models`）读不到能力字段时，用内置能力表补齐**，不会因为对端元数据缺失就把思考层级灰成「能力未知」。兼容接口拒绝思考参数时会自动移除不支持的参数后重试。
- 最大步骤是四档：24 / 68 / 120 / 无限制（新对话固定 24 步）。「无限制」表示不设轮数上限，循环仍受这几道闸约束：单轮最多执行 12 个调用、同一工具调用连续 3 次、连续多轮无进展、以及你点停止（工具调用总数本身不设上限）。旧对话或旧设置里的 `0` 是显式的「无限制」，负数和非法值仍回落到默认 24。

**轮数和工具调用次数是两套独立的量**，别把它们看成同一个限制：最大步骤管「模型能来回几轮」，工具调用管「这一次运行总共调用了多少次工具」。**工具调用总数不设上限**（24 / 68 / 120 / 无限制四档都一样），所以长任务不会跑到一半被「调用次数用尽」打断。仍然是「不限制」而不是「随便跑」：一轮内最多执行 12 个调用（超出的跳过并把结果回报给模型，循环继续下一轮）、同一个调用连续 3 次判死循环、连续 3 轮全部失败就停、有限档位仍由轮数封顶、停止按钮随时可用。

如果你真正想消掉的是**每次跑命令都弹确认框**，那和调用次数无关——命令类工具（`run_in_terminal` 等）的确认由 **VS Code 自己**决定，不看 HWChat 的权限预设。要一次配好：命令面板运行 `HWChat: 同步 VS Code 审批预设`（写入 `chat.tools.*` 用户设置，写入前会列出全部改动并要求确认，可随时还原）。四档从「关闭（全部询问）」到「全部自动批准（危险）」，后者写的是 VS Code 官方的总开关 `chat.tools.global.autoApprove`。注意：`chat.tools.edits.autoApprove` 在 VS Code 1.144 里是**按 glob 配置的映射**而不是布尔开关，HWChat 不会去写它（它的默认值本来就放行文件编辑，只排除 `.git`、`package.json` 这类敏感路径）。
- 每条完成的助手回复显示本轮 Token 消耗，统一换算为百万 Token（`M tokens`）；左侧对话记录显示该对话所有轮次的累计消耗。
- 左侧对话卡片上，正在运行的那条把「运行中」显示为**蓝色**（强调色），时间戳和 Token 数保持灰色——只给状态词上色，列表里一眼就能找到在跑的对话；等待授权的那条保持原色。
- 对话面板顶部第一行只放对话标题，标题下面一行是状态文字（「准备就绪 · N 个工具」/ 运行中）与项目名，再下一行依次放工作模式、API 配置、模型、**互联网参考开关**，以及 Skill、归档、导出、设置控件（「刷新模型列表」按钮已去掉：模型清单改成静默自动刷新，见下）；面板变窄时控件自动换行而不是压缩标题。下拉框与 Skill 按钮都只保留有信息量的部分——三个下拉框只留文字和一个固定间距的下拉箭头，Skill 只留星形图标（数量挪进悬停提示），把宽度让给标题。三个下拉框都按内容定宽、都不吸收剩余宽度（模式 60px、供应商 82px、模型 150px），模型框不会再把整行剩余宽度吸走变成一个大空盒子；控件行本身是**两端对齐**（`justify-content: space-between`）——控件原本被三个 `control-group` 分组包装，剩余宽度只会在**组与组之间**分配、组内仍是固定的 6px，于是出现「组内紧、组间松」的不等间距；现在三个包装层已从模板里去掉，八个控件都是 `.toolbar-controls` 的直接子项，剩余宽度被平均分到每两个相邻控件之间，因此任意两个相邻控件的距离完全相等，且首尾分别贴住左右两端（`gap` 保留作最小间距兜底，控件几乎填满整行时不会贴在一起）。
- 对话标题可以自己改：标题右侧的铅笔图标把它在原位变成一条带下划线的输入框，点对勾保存、点叉放弃（Enter / Esc 等价），上限 48 字符，自定义标题不会被首条消息的自动命名覆盖；改名不会改动 `updatedAt`，历史列表的顺序不会因为改名而跳动。
- 项目名显示在标题下方的状态行、紧跟状态文字右侧（整行左对齐，中间固定隔 8px，所以不会挡住状态文字），不占标题行的宽度：已绑定工作区文件夹时用橘黄色显示文件夹名；绑定不上时用红色显示「项目待建立」。标签是**纯文字**——没有色块、没有边框、没有内边距。这个状态是真实的——此时相对路径会落到第一个根目录、git 写操作会被拒绝，所以不猜一个目录名来显示。对话一旦开始改文件并绑定项目根，标签随即变成橘黄色。多条项目标签时同样从状态文字右侧按从左到右排列；项目名过长时先省略项目名（最多占半行），状态文字至少保留 45% 宽度。
- 这个标签显示的是**本对话涉及的全部项目**，不只有首次绑定的那一个：一个对话经常横跨多个项目（在 A 里做功能、顺手把 B 的对接改掉），只显示第一个时你既看不出它动过别处，也发现不了自己改到了别的项目。每次改动落盘成功都会记下项目根，按首次触达的顺序排列，同一个项目只记一次；被拒绝或失败的写操作不算「改过」，只读命令（`git status`）也不算。名字之间用 `·` 连接，一行放不下时折成 `+N`，悬停可看完整清单。升级前的老对话没有这份记录，但会从工具记录里的文件路径前缀反推，同样能显示多个项目。
- 输入框是单个圆角框：上方是文本输入区，框内底部单独一行放权限预设、最大步骤、思考层级，以及靠右的附件、语音、发送/停止按钮（附件在语音左侧）。这一行在任何宽度都保持单行不换行；变窄时按「思考深度 → 最大步骤 → 权限预设」的顺序隐藏文字前缀，只保留当前选中的选项。三项的新对话默认值是「每次询问 / 24 步 / 默认（模型官方）」；切换权限预设时会显示对应档位的风险说明，确认后对下一次发送立即生效。
- Agent 运行时输入框仍可编辑和发送。**每条新消息都会在每个小任务边界被重新判断一次**：判为相关的当场并进当前分支（任务树里从「排队」变成「已合并」，并在**同一个边界**就交给 agent 读，配的是「立即重新评估当前分支、按这条消息调整计划」那段说明），尚未执行的冲突步骤会跳过；判为无关的继续留在可见的任务树队列里，前一分支完成后自动继续。判断依据不只是分支标题，还包括实时上下文（任务清单进度、正在做的那一项、最近几步动作），所以「和正在执行的那条隔了多少条消息」不影响它会不会被读到 —— 以前只在发消息那一刻判一次，判成「排队」就一直压到整条分支结束。成本上每条消息在**同一条分支**上只重判一次。
- 运行中插入的每个问题都会立即生成自己的排队回答位，并最终把结果显示在对应问题下方，不再把后续问题的答案堆到上一条回复前面。
- 流式输出**只重画还在增长的那一块**：每个 delta 只重排正在写的那一段（纯文字尾巴直接追加到末尾文本节点，已有节点、悬停状态与过渡动画都不动），它上面的块保持原样——所以**已经显示出来的文字不可能再闪**。尾巴还会**先补全再渲染**：没写完的 `**粗体`、`` `代码 ``、`[文字](htt` 会在这一帧按最终形态闭合（与 Streamdown / `remend` 同一套做法），不会先显示字面量的星号再突然变粗。消息区显式关掉浏览器的滚动锚定（`overflow-anchor: none`），因为滚动位置每帧由 HWChat 自己算，两套补偿一起生效就会互相打架、看起来在轻微跳动。文件标签在整个流式过程中只有一个固定写法：核实结果按项目根缓存，重建出来的标签不会先短一截再长成真实路径。
- Agent 运行时可以自由向上查看历史；只有用户停留在底部时才自动跟随流式输出。执行期间输入框里的发送按钮会换成**红色高亮的停止按钮**（危险色底 + 呼吸光环，图标为实心方块），一眼能看出任务正在跑、点这里可以停；系统开启“减少动态效果”时不播放动画。按下停止是**真的停**：整组进程直接 `SIGKILL`（250ms 后补一枪），不再先 `SIGTERM` 等一秒，杀完立刻 abort 本次运行——连忽略 `SIGTERM` 的命令也会在半秒内消失。子进程按对话分开记账，停一条线程不会误杀另一条对话的命令。
- 支持从输入框粘贴图片、截图和文件，粘贴后会先显示本地缩略图。图片会以兼容 OpenAI 的多模态内容发送；任务缓存到期后会移除附件正文、图片 Base64 和缩略图，只保留名称、类型和大小摘要。
- **附件可以点开查看**（待发送的和已发送的都算），粘贴错了能先核对再发。从磁盘选的文件直接打开原文件本身，不复制、不移动、不重写；粘贴的文本用未命名文档显示，不落盘；粘贴的图片在扩展自己的 storage 里派生一份按内容寻址的副本再打开，所以工作区不会凭空多出文件，同一张图点多少次都只留一份缓存。
- **正文里提到的文件可以点开，也能直接在系统的文件管理器里定位**。回复里写的路径（`src/core/ids.ts`、`media/chat.js:745`）会渲染成一枚小标签而不是一段死代码：悬停轻微上浮、提示里给出完整绝对路径；**左键**在编辑器里打开（带行号就定位到那一行），**右键**弹出**四项**菜单——在 Finder / 资源管理器中显示（文件处于选中状态）、**在资源管理器视图中显示**（`revealInExplorer`：只展开 VS Code 自己的项目树并选中该文件，编辑器内容不变）、在编辑器中打开、复制完整路径。这两条「显示」是刻意分开的两件事——一条带你离开 VS Code 去系统文件管理器，一条留在编辑器里看文件在项目树的哪一层——所以是两个不同命令、两条不同消息；后者还会先判断文件是否在当前工作区内（`revealInExplorer` 对工作区外的文件静默无效，不报错也不移动，点了会毫无反应）。第二项采用 VS Code 自带菜单的措辞「在资源管理器视图中显示」而不是「在资源管理器中显示」，因为 Windows 上系统文件管理器也叫资源管理器，两项同名就无法区分。写在反引号里（引用格式）显示相对路径 + 行号；**没写引用格式的裸路径**同样认得出，但显示**完整绝对路径**，方便你在 VS Code 之外对着路径找文件。判定用扩展名白名单，`v0.2.4`、`e.g.`、`example.com`、网址、`--force` 这类不会长出菜单；带空格的路径只在反引号里认（正文里没有边界可判断起止）；中文直接贴着路径也能准确捞出路径本身。三平台命名分开：macOS 是 Finder、Windows 是资源管理器、其余是文件管理器。整个链路只读——显示和打开都不会移动、改名或重写被引用的文件。**引用先核实、再显示**：渲染之后会把每条引用回问扩展侧一次，由它实探文件系统——绝对路径要求真实存在；带目录的相对路径只按项目和各级工作区根确定，不会退而拿别处的同名文件顶替；裸文件名先按根目录拼（`package.json` 这类就在根上），拼不到才按文件名整棵树搜一次，而且**只有唯一命中才算数**（同名多份时猜错文件比不给引用更糟）；判不出来就降级成普通文本，原文一字不改，只是没有图标和右键菜单。查到的是另一个文件时（`extension.js` → `out/extension.js`），标签、悬停提示和点击目标会一起换成真实路径，不会出现「标签写 A、点开是 B」。
- 支持语音输入。HWChat 仅接收识别后的文字，不把音频写入对话缓存；识别文字仍需点击发送才会提交给当前 API。
- 模型回复会按 Markdown 结构排版，而不是一整段纯文本：标题（`#` ~ `######`）、有序/无序列表（按缩进嵌套）、表格（含对齐与横向滚动）、引用、分隔线都会被渲染出来，行内支持加粗、`行内代码`、删除线和 `[文字](链接)`。终端命令显示为独立的“终端命令”代码块，标题栏标出 **位置**（`loc=local` 本地终端、`loc=server` 服务器终端、或 `loc="自定义"`，服务器位置用警示色以便和本地区分）和 **工具**（`bash`、`zsh`、`cmd`、`powershell` 等），并提供经 VS Code 剪贴板确认的一键复制，复制内容只有命令本身、不含标注；写在列表项里的命令同样渲染成代码块，不会再漏成三连反引号。Agent 执行步骤中的提交内容、返回结果和实际命令也可直接复制，消息正文支持选择后用 `⌘/Ctrl+C` 复制。执行步骤汇总用“处理过程 · 共 N 步，改动 M 个文件”这类说法，尽量让不写代码的读者也能读。回复里的每段“我打算做什么”后面会紧跟它触发的那组步骤（做了什么、结果如何），说明与步骤按发生顺序交错出现，不用再上下对照；一组只有一步时不显示汇总标题，历史消息（旧数据）仍按“步骤汇总 + 正文”显示。不能一扫而过的提醒会按危险程度分级显示：写 `> [!DANGER] 短标题` 时标题变红、图标取亮黄警示色；写 `> [!IMPORTANT] 短标题` 时标题保持正文色、只有图标变橘黄；其它内容仍按普通引用显示。分级来自显式标记而不是猜测措辞，且 `[!DANGER]` 只留给三类**无法挽回**的伤害：**毁掉项目**（删掉或覆盖源码、未提交改动、已共享的历史）、**毁掉磁盘或系统**（格式化、往设备裸写、清空主目录、损坏 shell 与终端环境）、**泄露凭据或个人隐私**（密码、私钥、API key、token、证书、`.env`；身份证号、银行卡号、手机号）。整条判定只问一句：事情发生后，你还能不能把工作和机器原样拿回来？能，就不是危险；所以删临时文件、可逆改动、普通代码改动一律是纯文本，看起来再大也不标红。另外，你把 API key、私钥这类明文凭据贴进对话时，**界面不用等模型发现**，会直接在那条消息下面给出危险提醒，只说凭据类型和字符数、不回显密钥原文；身份证号、银行卡号、手机号同样会触发，因为这类号码发出去就无法像密钥那样吊销，所以建议只发打码后的片段。两类会分开成段给建议（密钥要吊销轮换，证件与卡号要挂失并留意盗刷）。识别带结构校验（身份证走 mod 11 校验位、银行卡走 Luhn、手机号按号段），`sk-xxxx`、`your_api_key_here` 这类占位符、commit hash、版本号、时间戳和普通订单号不会误报。收尾的「🔔 需要你做的」清单固定写成普通有序列表（`1. **动作**`），**不会**再出现 `[ ]` 复选框标记：这条规则写在 HWChat 自己的系统提示词里（`src/agent/followUpPrompt.ts`），渲染时还会再剥一次（`media/follow-up-format.js`），所以模型照不照做都不影响你看到的版面。只剥有序列表，`- [ ]` 这种真正的任务列表保持原样，消息原文也不改。
- 输入框支持 `⌘/Ctrl+V` 粘贴文字、图片、截图和文件；剪贴板同时包含文字和附件时会一起保留，并在 Webview 原生粘贴失效时自动使用 VS Code 剪贴板兜底。
- 除内置工作区工具外，HWChat 会发现并调用当前 VS Code 中通过 Language Model Tool API 暴露的全部扩展工具（不再固定截断在 100 个）；需要授权的工具只弹 VS Code 自己的确认框，不需要授权的工具直接调用，HWChat 不再叠加一层“允许 Agent …”弹窗。只有在你**打开 HWChat 面板或发送消息**时才会激活声明了语言模型工具但尚未运行的扩展（不再随 VS Code 启动无条件拉起其它 AI 扩展），模型调用了暂时缺失的工具时也会补激活一次再重试；网页、文本、Markdown 和差异内容可直接在编辑区预览。
- 可从任意历史记录点击“续接”，或运行命令 `HWChat: 在新对话中续接当前任务历史`。新对话保存来源对话的本地只读交接摘要，Agent 还可按需检索来源链中的旧消息，避免重复踩已经记录的坑。旧对话不会被复制或修改；本地保存本身不产生 API Token，但实际发送给模型的摘要和检索片段会计入输入 Token。

## 任务清单

任务需要拆成多步时，Agent 会写一份任务清单，而不是让你从正文里推断进度。清单位于任务树和输入框之间，按执行顺序编号：左边是这一步要做什么，右边是它的状态。

| 状态 | 显示 |
| --- | --- |
| 等待执行 | 绿色空心圆圈 |
| 执行中 | 绿色跳动的省略号 |
| 已完成 | 实心绿色圆圈 + 白色对勾 |

这三种状态标记是**内联 SVG 图标，不是字体字符**：形状和粗细在 macOS / Windows 上一致，颜色跟随主题，不会因为系统字体的大小、字重、有无该字符而变化。折叠箭头同理（箭头遮罩 + 旋转，不再用 `▸` / `▾` 字符）。

点标题即可收起或展开，和任务树一样。**新的一份清单到达时面板会自动展开**——折叠状态只在同一份清单内被记住，不会因为上一份被收起来就让新任务看起来没出现。Agent 始终只让一项处于执行中，每完成一步就更新一次清单，全部做完后保留整份清单作为记录。清单随对话保存，重载窗口后仍在；只有一步的任务不会创建清单。它是一个不需要授权的工具（`update_todos`），因为既不读也不写工作区文件、不执行命令。

### 清单里不会出现的两件事

**推送**和**版本号更新**不写进任务清单。这两件事在任务完成并验证之后**单独征询你**，你说同意才做。

这么定不是为了整洁：清单一旦写上 `6. 提交并推送`，你点「继续执行」时看到的就是这几条，而点继续意味着认可接下来要做的事——于是你从没说过的「推送」就借清单拿到了授权。而且这种条目通常不是模型故意夹带，而是「顺手把提交做完整」这类**看起来合理的扩写**，恰恰最不容易被逐条核对。

实现有两层，缺一层就会漏：拆分任务时的提示词规则（从源头不写进去），以及清单落库前的过滤（模型还是写了也摘掉，并在工具返回里要求它事后单独征询）。

过滤是保守的，只认真正的仓库动作：`git push`、`推送到远端 / origin / 分支`、`推送代码到 origin`、`升级版本号到 0.2.4`、`npm version patch`、`升到 0.2.4`。而 `实现消息推送`、`推送通知的开关`、`推送通知到用户设备` 是正常功能任务，`打包为 0.2.3 版本`、`修复版本号显示错误` 是构建和改文案——这些都不会被摘掉。如果整份清单都是这类条目，清单保持不变，而不是被清空。

### 中断之后：继续执行 / 取消任务

运行被打断（进程被杀、点了停止），或模型收尾时漏了打勾，清单顶栏最右侧会出现「继续执行」与「取消任务」两个按钮：

- **继续执行**：从断点接着跑，不重做已完成的部分。上下文是从存档重建的，模型能看到自己写下的清单和中断前每一步的工具结果，所以接着做是自然的；按钮只在「清单还剩没打勾的项」时出现。发出去之前会先撤掉中断标记，之后重新读一次存档：万一这一轮根本没跑起来（权限同意被拒、发送被拦住、发送前就出错），标记会被补回去，清单不会停在半路又没有办法继续。**它批准的是「接着做你已经要求过的事」，不等于批准清单里的每一项**——清单是模型写的计划，不是你的批准记录；模型若加了推送、升版本这类你没说过的条目，要单独问过你才能做。
- **取消任务**：清空这份清单，**不归档、也不留胶囊**——这是「别记着了」的意思。如果任务还在跑，会先停下来再清，避免收尾结算把刚清掉的清单又写回来。

顶栏分成**固定宽度**的几段（标题 / 状态 / 动作），每段内的文字左对齐：状态文字长一点短一点都不会再把标题顶着跑。任务树顶栏只有标题与节点数，没有这两个按钮。为把状态段压在一个固定宽度里，英文状态文案也从 `interrupted, can be resumed` 缩短为 `interrupted`——「可以继续」已经由按钮本身说白了。

### 归档胶囊

一份清单**全部完成**后立刻归档，不等这一轮运行结束：最后一项一打勾，清单就从输入框上方收走，「任务清单」折叠框消失，位置换成输入框上方一颗左对齐的纯色圆角矩形。这样「做完了却还占着位置」不会发生——模型标完全绿之后往往还要写很久总结，那段时间面板本来会被白占着；要是进程正好在这中间被杀或窗口被关，收尾结算根本没机会执行，这份「6/6 已完成」就会永远挂在面板上（打开对话时读一次清单，这种情况也会自动补归档）。

- 胶囊里**没有图标也没有文字**，鼠标悬停也不弹任何提示——颜色和左右顺序就是全部信息。读屏仍能读到「归档任务清单 N/M 完成」。
- **边框指示状态**：点开查看的那颗显示**红色边框**；鼠标悬停的那颗显示**浅红色边框**，用来指明指针停在哪一颗上（悬停不会改变胶囊本身的纯色）。边框画在胶囊内侧，所以胶囊大小不会因为出现边框而跳动。
- 点胶囊展开那份历史清单（标题写「已归档任务清单」，汇总带归档时间，边框改虚线），再点一次收起。
- **同一时刻只展开一个面板**：点开胶囊里那份历史清单时，「任务树」和「正在执行的任务清单」会自动收起并被锁住（标题变暗、点了会提示先收起归档），这样看到的永远只有一份清单；收起归档清单（点它自己的标题栏）或再点一次那颗胶囊，就会解锁并把它们还原成进入前的展开状态。遇到「面板右边被切、显示不全」「归档胶囊拖到最右还是被截断」时，命令面板运行 `HWChat: 复制布局诊断`（输出里含 `capsuleBar` 一节）：面板会自己量一遍 webview 的视口宽、文档 scrollWidth、侧栏 / 聊天栏 / 消息列表 / 输入框的矩形与横向溢出量，连同一份「越界元素」清单复制到剪贴板，用来分清是我们的 CSS 还是 webview 宽度与可见区域不同步。聊天栏有横向硬边界（`.app-shell` 用 `overflow-x: clip`）：任何内容再宽也不会把文档撑出横向滚动、然后把右侧挤出窗口。**但硬边界只有配合「列宽压住」才成立**：`.chat-pane` / `.message-area` 的网格列显式写成 `minmax(0, 1fr)`，否则隐式列是 `auto`、会被最宽的子元素按 max-content 撑开（实测：870px 视口里归档胶囊到 40 颗时，那一列涨到 1387px，右侧 514px 直接被裁掉且无法通过滚动看到 —— 归档栏「拖到最右还是被切」与「对话框被截断」都是它）——macOS 的覆盖式滚动条不滚动时不显示，那种情况看起来就是「右边被切、又找不到滚动条」。面板区高度有上限（**28vh 且不超过 260px**，比早期版本的 44vh/360px 小得多）、超了在内部滚动（**滚动条常显**，滚轮和拖动都能滚），不会把输入框挤出窗口，也不会把上面的对话挤到看不见（窗口很矮时会再让一档）；展开某份归档时，另外两个只剩标题栏，面板区会拿到更高的上限，一次能看更多条目。
- 一份对话可以有多份归档，新的排在上一个的右边；颜色是从**浅蓝 `#7cbef0` 到深蓝 `#1e4fd8` 的一段连续渐变**——按位置均匀取样，所以相邻两颗之间的色差相等，看起来是一段过渡而不是几块跳色；越靠右越深。
- 胶囊**永不换行**，宽高比恒为 **3:1**，固定高 10.67px、宽 32px。胶囊超出栏宽时**横向滚动，但不显示滚动条**（6px 的横条快赶上胶囊一半厚度，又挡视线又抢注意力）：鼠标滚轮悬停在胶囊栏上即可左右滚，也可以**按住鼠标横向拖动**（光标是「可抓取」，拖动中变「抓住」；触摸屏用系统原生惯性滚动）；滚到两端后滚轮交还给页面的纵向滚动。尺寸始终不变；新归档加进来时会自动跟到最右端一次，而展开/收起引起的重渲染不会动你的滚动位置；圆角约 3px，始终是圆角矩形而不是整圆胶囊。
- **归档不设数量上限**：胶囊栏本来就能横向滚动，所以一条对话完成多少份清单就保留多少份（此前卡在 12 份，长任务里最早那几份会被静默挤掉）。单条归档自身仍限制 40 项，所以存储增长与实际完成的任务数同阶。中途被停止或失败、仍有未完成项的清单**不会**归档，见下方「没做完的清单」。
- 归档随对话落库（manifest 的 `todoArchives`），重载窗口后仍在；磁盘上的脏数据在读入时会被丢弃，不影响对话本身。

### 没做完的清单（中断 / 未完成）

一轮运行结束时没全绿，清单都不会变成胶囊，而是原样留在面板上；「执行中」那一项降级成**等待执行**（绿色空心圆圈），不再播跳动动画——没人推进它时不该假装还在跑。标题上补的那句话按**这一轮是怎么结束的**分成两种：

- **已中断，可继续**：用户点了停止、请求报错、关窗口（或进程被杀）。工作是被半路掐断的。
- **未完成，可继续**：Agent 正常跑完了，只是模型漏了给最后一项打勾。这不是中断，所以用中性色标注，不会用警告黄误导成「被掐断」。引擎不会替模型自动打勾——清单是模型对「做完了没」的陈述，代打勾等于伪造进度；预防措施在 system prompt 里：结束本轮前必须再读一遍清单，做完的项（**包括最后一项**）要补一次 `update_todos` 置为完成。

后续处理两种标记一致：

- **接着做**：让 Agent 继续这份任务，它会沿用原清单、把当前项改回执行中，全部完成后照常归档成胶囊。这条续跑指令**只针对这份清单生效一次**：面板把它绑定到清单里还没打勾的条目上，而不是把「继续执行任务清单」这句话本身当成任务目标，所以期间再提一个不相干的新需求会被排到队列里（任务树显示「排队」），不会被合并进这一轮。清单已全部打勾、或本来就没有清单时，它不生效。
- **换新任务**：直接提新需求即可，全新的清单会替换旧清单，但**丢掉进度式的替换会被拒绝**：新提交的清单里若少了现有清单已标完成的条目，`update_todos` 直接报错、一个字都不写库，并告诉模型照抄现有条目、只重排还没做完的部分。（没有这道闸门时，模型「继续执行」常常按最近几轮对话重新归纳一份计划，悄悄把六条已验证的步骤扔掉——这是真实发生过的。）闸门只在三种情况放行：你本轮明确要求重规划（「重新规划一下清单」「把之前的清单丢掉」）、旧清单已全部完成（本来就要归档）、或旧清单一条都没完成（没进度可丢）。
- **模型现在能看到它要接着做的那份清单**：`update_todos` 的返回值是 `tool` 消息，会被请求过滤掉，而清单本身只存在对话摘要里——所以「继续执行尚未完成的条目」这句话过去是**不带清单**发出去的。现在请求会把 `<task_list>` 块注入 system 消息，带 `[x]`/`[>]`/`[ ]` 状态、剩余条数和一句明确的 `Next item to work on: #N`。清单已全部完成或本来就没有时不注入。

两个标记随对话落库（manifest 的 `todosIncomplete` / `todosInterrupted`），**互斥**：同一份清单只会挂其中一个，换新清单或归档时一起清空。老存档没有这些字段，载入时按「没标记」处理。

## 并发对话

每个对话各自跑自己的 Agent 线程，互不阻塞：

- 对话进行中可以直接点「新建对话」或别的历史记录，被切走的那条继续在后台跑，历史列表上用蓝点标出「运行中」。
- 点「新建对话」的规则：**当前这条还有内容**就新建一条（侧边栏立刻多一张卡片，右侧切到它的空对话框）；**当前这条本来就是空的**（0 条消息）就不再新建，只把焦点交还给这个空对话框——否则连点会把历史堆成一串「新对话 · 空对话」。历史上已经堆起来的空对话会被定时清理收敛成最新的一张（5 分钟宽限期，空对话没有任何内容可丢）。
- 停止按钮只停当前显示的那条线程；归档、删除也只拦同一条对话。
- 模型 / 模式 / 技能只在这条对话自己忙时锁定，不会因为别的对话在跑就整块锁死；权限预设、最大步骤、思考深度在运行中**故意保持可改**（下一次发送生效），见下方「每条对话独立的设置」。
- 后台线程结束只刷新历史列表，不打断当前正在读的对话的滚动位置。
- 历史列表按**新建时间**排序（新的在最上面），不按最后活动时间。在旧对话里发一条消息不会把它顶到列表最上面，每条对话的位置是固定的，不用每次回复后重新扫一遍；置顶的仍然浮在最前，归档的仍然沉在最后。
- **复制带图片的消息 = 文字 + 图片一起复制**：点消息左上角的「复制」，剪贴板里会同时放入 `text/plain` 和 `image/png`，粘到输入框（`⌘/Ctrl + V`）时文字进输入框、图片变成一条待发附件 —— 不用再单独把图存下来。
  - 复制的是**原图**，不是界面上那张 160×120 的缩略图；jpg/webp 等格式会先转成 PNG（剪贴板的异步写入只接受 PNG）。
  - 剪贴板一次只能放一张图片，所以多图消息只带第一张，并会提示一句。
  - **鼠标悬停到「复制」上时就开始预取原图并转好 PNG**，所以点下去只剩一次写入 —— 大图不会因为「用户手势过期」而只复制到文字。
  - **键盘也能用**：Tab 到图片按 Enter 打开图片，Tab 到「添加到输入框」按 Enter/空格则把图加进输入框（两个入口不会互相抢按键）。
  - 环境不支持写图片时（旧内核、附件已被内存淘汰）**照样把文字复制成功**，并明确告诉你「只复制了文字」，不会让你以为复制全了。
- **已经发出去的图片/附件可以再拿一份放进输入框**：把消息里的图片直接**拖到输入框**（输入框会亮起强调色描边，松手即成为一条待发附件），或者点图片右上角的「添加到输入框」。两条入口都通向同一条路径 —— 界面只把附件标识送上去，内容由扩展侧按 `id` 从内存里取（图片有 `dataBase64`）；万一那条已经被缓存淘汰了，就按路径从磁盘重读，读取器与「选文件」完全相同（大小上限、敏感文件、二进制判定一致）。文本附件同样可以拖。从 Finder / 资源管理器直接拖文件进输入框也可以（按文件处理，等同于粘贴文件）。
  - 复制出来的是**独立的一条**（不带原附件的内部句柄），拖两次就是两条 —— 需要两份上下文时不用反复翻历史。上限与「选文件」一致：最多 20 条、总量有上限。
- **排队中的消息在消息气泡里编辑，在任务树里删除**。
  - 编辑入口在那条消息的气泡里（底部一枚「还没执行」标记 + 「编辑这条消息」）：点开是**悬浮编辑框**（独立层级、盖在面板中央），整条消息的宽度都给它，长内容不用挤在任务树那一行里看。`⌘/Ctrl + Enter` 保存，`Esc` 或点遮罩空白处取消。浮层在消息列表**之外**，所以 agent 流式输出时消息列表怎么重排都碰不到它——不会再出现「点了没反应」「光标跳回开头」「中文输入法被打断」。
  - **agent 会等你改完**：打开浮层时后端就在任务队列上挂了一道闸门，agent 走到这条消息时会**停下来等**（浮层标题右侧显示「agent 正在等你改完」并带呼吸点）。保存后它立刻读到改好的新内容继续执行；取消则按原内容继续。等待上限 **5 分钟**（防止编辑框开着一去不回把任务卡死），超时后按已保存的内容继续。
  - 还**在队列里**时（包括刚发出、分类还没回来的 `routing` 那一小段），保存就是改这一条本身：队列里持有的就是那条请求，所以 agent 下一轮直接读到新内容——不用撤单重发，也不会多出一条消息；**任务树的排队标题与存档里的用户消息一起改**，两边不会对不上。编辑只换文字，粘贴的图片等附件不会丢。
  - 编辑期间不会重画消息列表：流式输出、任务树更新都先记下来，退出编辑时才补一次，否则编辑框会被重建，光标、选区和输入法正在拼的字都会丢。
  - **删除**（任务树行上的按钮）会把排队请求连同它的占位回复一起从磁盘删掉，不留下「排过队但从没跑」的孤儿消息。节点本身留在任务树里标成**已取消**——任务树是这一轮发生过什么的时间线，抹掉节点等于假装你没发过那句话。
  - **执行中**的节点不给任何编辑入口。agent 已经把这句话读走并在跑，后端也改不了那条 request（`editPending` 必然返回 false），以前在这里点「编辑」实际会走「把改过的内容当成新消息再发一遍」——同一件事被排队做第二次。要换方向就在输入框里补一句（会作为「相关指导」合并进当前分支），或者先停止。
  - 节点**执行完成**之后，任务树那一行给「编辑」：历史就是历史，删除会被拒绝（附一句原因）；编辑框同样开在消息气泡里，标题写明「编辑并重新发送」，保存后把改过的内容**当成一条新消息发出去**——你可以重新表达意图，但过去不会被改写。能不能原地改取决于队列是否还持有它，不靠状态猜。
- **「互联网参考」开关（工具栏，原「刷新模型列表」的位置）**：点一下就打开，这条对话从此**先上网找成熟方案，再动手**。
  - 打开后 Agent 的工作方式变成三步，写在系统提示词里、每次请求（含点「继续」）都会重新带上：**① 调研** —— 用 `search_github_repos` 找相关成熟开源项目（按星数排序，带许可证与最近更新），用 `search_web` 找概念与官方文档入口，再用 `fetch_url` **读原文**（官方文档 / 规范 / 参考实现），并逐条记下「URL + 一句结论 + 与本项目的差异」；**② 对齐计划** —— 把调研结论并进任务清单，第一条就是调研，剩下的按学到的东西调整甚至推翻原来的想法；**③ 执行** —— 按读到的方案动手，与来源不同时用一句话说明原因。
  - 三条硬规矩也写进了提示词：**结论必须带 URL**（没读过就不能引用）、**不许把搜索摘要当依据**（摘要只是找到原文的线索）、**搜不到就明说「没找到权威方案」并给出 2-3 个候选与代价**，不许把猜的包装成调研。引用代码前要先看许可证，并核对版本与前提是否和本项目一致。
  - 三个联网工具**只在开关打开时才会出现在工具清单里**（关着时模型根本看不到它们，不会自己去查网）：`search_github_repos`（GitHub 仓库搜索，找「别人怎么做的」最直接）、`search_web`（通用网页检索，结果明确标注「只是线索」）、`fetch_url`（取网页/README/JSON 并转成可读正文）。`fetch_url` 只允许 http/https 且**拒绝本机与内网地址**（`localhost`、`127.x`、`10.x`、`192.168.x`、`172.16-31.x`、`169.254.x`、`*.local` 等），防止模型顺手拼一个开发服务器地址去取。
  - **开关本身就是授权，所以这三个工具不会逐次弹审批**：一次调研往往要十几次检索，若按「读文件」的档位逐次确认，点到手软。开关是每对话独立、默认关闭、需要你主动点的，联网这件事的同意已经在那一处给出；真正危险的方向（读本机/内网）另外由地址检查硬挡。开关关着时若模型仍硬调这些名字，会得到一句明确的「互联网参考没有打开，请先点工具栏地球图标」，而不是含糊的「工具未被允许」。
  - 开关**归属这条对话**：在 A 对话打开不会让 B 对话也联网；随对话存档，重载窗口后仍在。默认关闭。运行中也可以切换，和其它三项一样「下一次发送生效」（本轮用的是运行开始时的设置快照）。
  - **`fetch_url` 抓的是正文，不是整页标签汤**：HTML 页面交给 [`defuddle`](https://github.com/kepano/defuddle)（MIT，9.8k★，Obsidian Web Clipper 的抽取内核）转成干净 Markdown —— 导航栏、侧边栏、面包屑、Cookie 横幅、页脚都被丢掉，标题层级、列表、链接、代码块、表格保留下来。实测 MDN 一页 **327 KB HTML → 4057 字 Markdown**。抽出的正文不足 200 字（比如接口返回的是 JSON 片段或极简页）就自动**回退**成整页文本，绝不返回空内容；工具输出里会写明这次是「正文抽取」还是「整页文本（已回退）」，方便模型判断读到的是什么。
  - **开源许可证合规**：`defuddle` 等 19 个第三方库是 **bundle 进 `extension.js` 一起分发**的，MIT / BSD-2 / ISC 都要求再分发时附带版权声明与许可全文。所以仓库里有一份 [`THIRD-PARTY-NOTICES.md`](./THIRD-PARTY-NOTICES.md)，由 `scripts/third-party-notices.mjs` 按 **esbuild 的 metafile**（只看真的从入口走得到的包）自动生成并随 VSIX 一起发布；任何一个包找不到许可证文件都会让打包**失败**，不会静默漏署名。清单目前是 19 个包：`defuddle`(MIT)、`@mixmark-io/domino`(BSD-2)、`temml`、`htmlparser2`、`@xmldom/xmldom`、`@acemir/cssom`、`linkedom`(ISC)、`mathml-to-latex`、`entities`(BSD-2)、`css-select`(BSD-2)、`domutils`(BSD-2)、`css-what`(BSD-2)、`turndown`、`domhandler`(BSD-2)、`dom-serializer`、`nth-check`(BSD-2)、`domelementtype`(BSD-2)、`uhyphen`(ISC)、`boolbase`(ISC)。`npm run package` 现在是「编译 → 刷新清单 → 打包」三步，清单不会过期。

- **每条用户消息都带执行状态徽标**，四种颜色一眼扫出「哪条没跑」：**还没执行**（橙 · 虚线，队列里等着）、**执行中**（蓝 · 呼吸点，agent 正在跑这条）、**已执行**（绿 · 实线，跑完/失败/被停止都算）、**已跳过**（灰 · 虚线，这一轮结束 agent 都没读过它 —— 也就是被忽略的那条）。悬停徽标有解释，鼠标停在上面就能确认每个状态的含义。一次运行里排了多条消息、中途停下再点「继续」时，就看这几个颜色对齐任务，别再靠回忆。
  - 状态记在**消息本身**（`executionStatus`），不是只存在任务树里：所以运行结束、切到别的对话再切回来、甚至重启 VS Code 之后，气泡上的状态都还在。老版本留下的消息没有这个字段，就不画徽标 —— 认不出状态时不猜，写一个「已执行」反而会让人以为跑过了。
  - **「已跳过」是特意做出来的**：任务树结束时会把它自己的节点统一标成结束状态，光看任务树分不出「跑完的」和「排了队一次没跑的」；这里按「agent 有没有真的读过这条消息」（`activated`）判定，把没读过的标成已跳过。进程异常退出时来不及结算的，下次启动会按「跑过的算已执行、没跑过的算已跳过」收口。

- **你发出的长消息默认折叠**：超过约 480 字或 12 行（满足其一即可）就只显示开头几行、底部渐隐，并给一个「展开全文」按钮；短消息完全不折叠、也不出现按钮。折叠只切一个 CSS class，正文里的 Markdown、表格、代码块、文件标签都不重建，所以展开时选中状态与滚动位置都还在，而且后面有新消息触发整段重绘时，已展开的那条仍然是展开的。
- 输入框里没发出去的文字属于**你打它的那条对话**。切换对话时草稿会存下来、切回去自动恢复，这条对话里敲的内容不会再出现在另一条对话的输入框里被误发出去。

### 每条对话独立的设置

- **遇到方案决策时它会停下来问你**：当两个以上方案都可行且结果差异明显、需求留了真选择、改动难以回滚、或者要做的只有「看到才能判断」（界面/流程/生成物）而布局没被指定时，agent 会调用 `ask_user_choice` 弹出一张卡片，**每个方案必须写清三件事**：能做成什么、做到什么地步（含刻意不做什么、哪里还粗糙）、代价（时间 / 改动面 / 风险 / 后续维护）。卡片出现后 **agent 会一直等**，在你点选之前它不会自己挑一个往下做。
  - 反过来也不会变成「每步都问」：只有一种合理做法、代码或对话里已有答案、可逆的外观选择、你已经决定了、或只是已批准计划里的常规步骤时，它不会问。
  - 点选后它会按你选的那个继续，不会擅自换方案；如果发现那个方案做不到你的期待，它会先说明原因再重新征询。
  - **卡片可以收起**（标题行右侧的「收起/展开」）：收起后只留问题一行、选项全部隐藏，先把上面的对话翻完再展开决定。
  - **三个都不合适？不用先选** —— 直接在输入框写下你的做法发出来，那句话就是答案：它会按你的做法继续，不会把你的做法硬套成上面某个方案，也不会擅自扩大范围。
- **执行流水里每一行都能读出「在干什么」**：命令类步骤显示为 `` `npm test` → 退出码 0 · 12.4s `` 而不是只有「命令退出码 0」；摘要会先抹掉 `Authorization: Bearer …`、`?token=…` 这类凭据（非敏感参数保留，否则认不出命令）。
- **技能的「触发词」是独立字段，不会被描述截断吃掉**。技能描述按三段解析：摘要 / 适用场景（`USE FOR:` `Use when:` `适用：`）/ 触发词（`Triggers:` `触发词：`，或 frontmatter 里写 `triggers:`）。触发词不参与摘要的 240 字符上限，会原样进入路由表（`- id | 名字 | 摘要 | 适用：… | 触发词：…`），所以把它写在描述第几段都不影响模型看不看得见；技能面板里每个技能只占一行摘要（描述超出用省略号），**悬停**可以看到完整摘要、适用场景与触发词 —— 38 个技能时列表从 7 屏降到约 4.7 屏。摘要本身最长 180 字符、适用 200、触发词 160，超长会显式加省略号。
模式、模型、权限预设、最大步骤、思考深度、互联网参考都是**这条对话自己的属性**（`src/core/conversationControls.ts`、`src/core/modes.ts`）。

- **新对话的初始值固定为「每次询问 / 24 步 / 默认（模型官方）」**，不读取 `settings.json` 里的旧值。旧版本会把面板选择写进全局设置，于是 `hwchat.permissionPreset: autopilot`、`hwchat.agentMaxSteps: 0` 这类残留会让每条新对话一开就自动执行、无限步——现在这几项键仅保留注册（不报未知配置项）并标记废弃，**不再参与判定**；`HWChat: 显示权限来源` 仍会把声明值原样列出，便于对账。
- 在对话 A 把权限预设改成「完全访问」，正在后台跑的对话 B 不受影响；B 把最大步骤改成 8，也不会截断 A 的下一轮。
- 面板上的改动写回当前对话，不会改动其他人的设置，也不写全局配置。
- **权限预设、最大步骤、思考深度都可以在任务运行中切换**（与 Copilot 一致），三项都**从你下一条消息开始生效**，不会改动正在飞的那一轮。本次运行从开始那一刻就持有一份设置快照，所有工具调用都读它，所以运行中切换不会把当前这一轮变成「一半旧一半新」；新值写入对话存档，任务结束后的第一条消息就用它。运行中每个控件都会明示「下一次发送生效」。
- 放宽到 Autopilot / 完全访问仍需二次确认，确认后才写入。
- 存档里的非法值（拼错的预设、字符串形式的步骤数、非字符串的项目根）在载入时丢弃并回落到默认值，不会带着脏值去运行。

## git 与项目边界

HWChat **不会主动提交 git**。git 写操作（`add` / `commit` / `push` / `tag` / `reset` / `clean` / `merge` / `rebase` / `checkout` / `restore` / `stash`）只在两种情况下放行：

1. 用户在这条对话里明确要求提交、推送或打标签——**运行已经开始之后补发的那句话也算**（「不要提交 / 先别推送」这类否定写法不计入）；
2. 已启用的技能规则要求「完成任务后提交」——这条等同于用户要求。

提示词里写了同样的硬规则，但真正的边界在运行时：`ToolExecutor` 逐条解析命令里的 git 子命令，未获授权直接拒绝并说明原因；桥接的 VS Code 工具（如 `run_in_terminal`）也会检查 JSON 参数，避免换个通道绕过去。只读检查（`status` / `diff` / `log` / `show`）始终允许。

**提交只落在本次对话所属的项目里**：

- 每条对话首次写入文件或显式指定 `cwd` 时绑定一个项目根（`projectRoot`）。相对路径、命令的默认 `cwd`、新建文件都归属这个项目，不再落到「多根工作区里的第一个根目录」。
- git 写操作前用 `git rev-parse --show-toplevel` 取真实仓库根，要求它与项目根一致；仓库根若还罩着另一个工作区项目，也会被拒绝（一次 `git add -A` 会把别的项目改动一起收进去）。
- 项目根尚未确定时，git 写操作只接受显式 `cwd`，不会把「默认落到第一个根」当成项目归属。

## 版本号：只在任务完成后询问

HWChat **同样不会主动升版本**。版本号是用户的决定，不是收尾步骤：

- 不许自己改 `package.json` / `package-lock.json` / `manifest.json` 等清单里的 `version` 字段，也不许跑 `npm version` / `yarn version` / `cargo set-version` / `standard-version` / 打 git tag。
- 该问的时候才问，而且只问一次：
  - **短任务**：这轮对话里提到的所有问题都做完、验证过之后，问「要不要升版本 / 要不要提交」；
  - **长任务**：在明确的阶段边界，或整个任务做完之后问；
  - 任务进行中不问，也不把这个问题塞进某个未完成步骤的中间。
- 用户没有明确答应之前，版本号和 git 历史都不动，继续把剩下的活干完。用户自己要求（「升到 0.2.3」）或已启用技能要求时，视同授权。

运行时也有闸门（`src/agent/releasePolicy.ts`）：写入版本清单时比较项目自身的 version 字段，变了就拒绝并说明「先去问用户」；`npm version` 一类命令同样拒绝；桥接的 VS Code 工具参数也会检查，换个通道绕不过去。只读查询（`npm --version`、`git tag -l`）始终允许。

判定只看**项目级**版本号：`package-lock.json` 里依赖的版本变化、`Cargo.toml` 里依赖表写的 `version` 都不会被误判成升版本；清单解析失败时宁可不拦，也不打断正常的文件修复。

## Skills

HWChat 扫描以下本地格式：

- `.hwchat/skills/*.md`
- `.agents/skills/**/SKILL.md`
- `.claude/skills/**/SKILL.md`
- VS Code 全局存储中的用户 Skill 目录
- `~/.copilot/skills/**/SKILL.md`

星标按钮打开“本次对话使用的 Skill”面板。**面板的勾选状态直接对接“本地skill快捷调用”扩展**：已安装时，它维护的全局勾选清单（`~/.copilot/.skill-quick-launch.json` 的 `active`）就是每个新对话的初始勾选；此后在对话面板里勾选 / 取消**只影响当前这条对话**，不会写回那份清单——一次任务里的临时取消，不该顺手改掉以后所有对话的默认值。想改默认值请到“本地skill快捷调用”面板里勾。勾选后 Skill 才参与对话调用，但“已勾选”不等于每轮都加载：`route` 模式下，Agent / Plan 会先看到轻量路由表，仅在任务匹配时通过 `load_skill` 读取全文；Chat 模式会按任务文字匹配后预载。每条回复只显示本轮真正读取过的 Skill 名称和数量，并把最近调用时间同步回快捷调用扩展（只写时间戳，不改勾选）。扩展被安装 / 卸载 / 启用 / 停用时面板会立刻跟着变（监听 `extensions.onDidChange`），不需要重载窗口；对面改了勾选，这边也会跟着更新。

未安装“本地skill快捷调用”时，点星标**只显示安装提示**（标题带“未安装”角标）与“打开扩展详情”按钮，不再列出技能：没有它，每个新对话的默认勾选就没有来源，这时面板的职责就是把用户送去安装。按钮优先用内置命令 `extension.open` 在 VS Code 内打开详情页（装完能顺手勾选），失败退回 `workbench.extensions.search`，最后才用 `vscode.env.openExternal` 打开商店网页。**卸载扩展不会删除 `.skill-quick-launch.json`**，所以卸载后 HWChat 也不再读它——否则那 30 多条残留的 `active` 会让每个技能都显示成“默认启用”并自动打勾，看起来像扩展没卸干净。技能本身仍会从 `~/.copilot/skills/` 扫出来（那是 Copilot 的技能目录，不随扩展安装卸载变化），只是不再被这份无主的状态文件影响。

非快捷调用来源的 Skill（`.hwchat/skills`、`.agents/skills`、`.claude/skills`、扩展自带的用户 Skill）同样按对话选择；`always` 模式下的 Skill 直接加入本轮系统上下文。支持简单 YAML frontmatter 的 `name` 和 `description`。

设置页「通用 → 界面语言」可在中文与 English 之间切换，也可设为「自动」跟随 VS Code 的显示语言。切换后对话面板、设置页、通知和错误提示会立即换成对应语言，不需要重载窗口。命令面板里的命令标题与设置项说明跟随 VS Code 自身的显示语言（扩展的 NLS 机制）。

## 权限与隐私

- API Key 使用 VS Code `SecretStorage`，不会写入项目或对话记录。
- 首次发送前明确展示数据流向并取得同意。
- 提供“每次询问 / 风险操作询问 / Autopilot / 完全访问”四档权限预设（不提供逐项自定义组合），设置页内置各档位边界对照表，输入框下拉项也带同源说明：

| 档位 | 读取 | 写入 | 只读命令 | 正常命令 | 危险命令 | 敏感文件 |
| --- | --- | --- | --- | --- | --- | --- |
| 每次询问 | 逐次确认 | 逐次确认 | 逐次确认 | 逐次确认 | 直接拒绝 | 禁止 |
| 风险操作询问 | 自动允许 | 自动允许（工作区内） | 自动允许 | 自动允许 | 逐次确认 | 禁止 |
| Autopilot | 自动允许 | 自动允许（工作区内） | 自动允许 | 自动允许 | 自动允许 | 禁止 |
| 完全访问 | 自动允许 | 自动允许（工作区内） | 自动允许 | 自动允许 | 自动允许 | 逐次确认 |

- 只读命令是 `ls`、`git status`、`grep` 等无副作用命令；正常命令是安装、构建、提交等常规命令；危险命令是提权、破坏性删除、磁盘擦写、强制推送、把网络脚本管道给 shell 等操作。
- 未受信任工作区中的写入和命令始终关闭。
- `.env`、证书、私钥、SSH/AWS/Kubernetes 凭据路径按“敏感文件”策略处理：默认禁止，设为“逐次确认”时每次访问都会弹窗说明目标文件，设为“允许”才自动读取。
- 工具授权在**对话面板内**给出（输入框上方一张卡片：拒绝 / 允许一次 + 可折叠详情），不使用会锁住整个 VS Code 窗口的模态对话框，等待授权时仍可拖动分栏、切换对话、编辑文件。若该对话在后台等待授权，历史列表会用黄点标出「等待授权」，切回去即可处理；任务被停止或结束时授权请求立即作废。
- 子进程环境会移除常见 Token、Secret、Password 和 API Key 变量。
- 远程 API 地址必须使用 HTTPS；只有本机 `localhost`、`127.0.0.1` 和 `::1` 可使用 HTTP。
- 无遥测。对话、Skill 和 Agent 审计记录默认只保存在本机，可在设置中全部删除。

详细边界见 [SECURITY.md](SECURITY.md)。

## 历史与缓存

- 每条消息独立存储，采用同目录临时文件、原子替换和恢复备份，索引损坏时会从磁盘重建。
- 流式回复每 1.5 秒持久化；扩展异常退出后保留已经生成的内容。
- 对话支持固定、归档、恢复、搜索、删除和流式导出。
- 被续接对话引用的来源历史会受自动清理保护；手动删除来源前会提示其对后续按需检索的影响。续接对话仍保留创建时的本地摘要。
- 已完成任务的思考过程、Token 输入/输出明细、工具输入/输出和附件正文会按保留时间自动瘦身，但最终回复、累计 Token、实际调用的 Skill、工具摘要、文件列表和审批结果会保留。
- UI 和模型上下文都有条数与字节上限；附件还有单文件、数量和总容量限制。
- 超出磁盘预算时按最久未使用顺序淘汰普通对话，固定、归档和执行中的对话不会被删除。

## 开发

运行要求：VS Code `1.106.0` 或更高版本，Node.js 20+。

安装已构建的 VSIX：

```bash
bash scripts/install-local.sh
```

`scripts/install-local.sh` 会自动挑项目根目录下最新的 VSIX，并自动定位 VS Code 的 `code` 命令行工具；同版本会带上 `--force` 覆盖旧安装。找不到 `code` 时它不会硬失败，而是打印两条替代路径（`Shell Command: Install 'code' command in PATH`，或扩展视图 `⋯` → `Install from VSIX…`）。`--check` 只报告会装哪个包、当前装了什么，不执行安装；`--list` 只列已装版本；VS Code 不在默认位置（例如 Insiders）时用 `HWCHAT_CODE_CLI=/path/to/code bash scripts/install-local.sh` 指定。

也可以用一行命令直接装，不依赖脚本：

```bash
code --install-extension "$(ls -t hwchat-*.vsix | head -n 1)" --force
```

这条命令总是安装项目根目录下最新的 VSIX，不会因为版本号变化而失效。

> 装完必须重载窗口（`Developer: Reload Window`）才生效：聊天界面跑在你已安装的扩展宿主里，不重载就仍是旧代码。

在 VS Code 中打开命令面板，执行 `HWChat: 打开对话面板`。首次使用时进入设置，创建一个 API 配置档并保存 API Key；密钥只会进入 VS Code SecretStorage，不会写入 `settings.json`、项目文件或 VSIX。

从源码构建：

```bash
npm install
npm run check
npm test
npm run package
```

构建结果为项目根目录下的 `hwchat-<version>.vsix`，`<version>` 取自 `package.json`。同一扩展已发布过的版本不能覆盖上传 Marketplace，发布新构建时必须递增版本号。

打包时无需修改本 README：扩展视图与 Marketplace 会直接从 `package.json` 读取版本号、仓库、许可证和问题链接，这里不再重复。版本历史见 [CHANGELOG.md](CHANGELOG.md)。

扩展图标使用 `resources/logo.png`。在 VS Code 中按 `F5` 启动扩展开发主机。

界面里的所有状态标记与折叠箭头都来自 `media/ui-icons.js`：一套自绘的扁平内联 SVG（16 格网格、四周 2 格留白、只用 `currentColor`），形状在这里改一处即可全站生效，规格由 `src/test/uiIcons.test.ts` 约束（同 viewBox、无硬编码颜色、描边宽度下限、CSS 遮罩与 JS 路径不许各画一套）。它不依赖任何第三方图标库，因此没有额外的许可义务。`node test/check-icons-dom.mjs` 会验证 `chat.js` 确实把图标构造成了 SVG，而不是退回到文字字符。

**工具栏与输入框上的按钮用的是另一套 24 格图标**（`src/views/webview.ts` 的 `icon()`）：16 格那套给正文与状态标记，24 格那套给按钮，两边各管一处、互不混用。它们的几何由 `node test/check-icon-geometry.mjs` 约束——那套路径是手写的，肉眼「大概居中」并不等于居中：墨迹可以整体偏出中心（`.icon-button` 的居中作用在 `svg` 盒子上，不是墨迹上），可以探出 viewBox 被静默裁掉（SVG 最外层默认 `overflow: hidden`），也可以圆心偏离盒子中心，让加载态的 `spin` 转起来是绕着盒子中心甩而不是原地打转。脚本真解析路径（含弧与曲线）算出每个图标的墨迹包围盒，把这三条一起断言；`--report` 只打印实测几何，改图标时用来看数字。

**助手输出里的少量 emoji 也走同一套图标**（`🔔 📌 💡 🚀 🔍 ⚠ ✅ ❌ 📝` → `bell` `pin` `bulb` `rocket` `search` `warn` `check` `close` `pencil`）。系统 emoji 字体画出来是彩色、带高光的，和这套单色扁平界面不是一回事，而且「扁平/单色」由字体决定、CSS 改不动。替换在渲染后的文本节点上做，`<pre>` / `<code>` 里跳过（代码里的 emoji 是内容本身），只对助手输出生效，未登记的 emoji 原样保留。

正文里文件引用的识别在 `media/file-reference.js`（纯函数：扩展名白名单判定、行号后缀拆分、相对→绝对、正文裸路径扫描），平台命名、入参清洗和「文件是否落在工作区内」（`isInsideWorkspace`）在 `src/agent/fileReveal.ts`，「这个引用到底是哪个文件」的判定在 `src/agent/fileReferenceResolve.ts`（存在性由调用方注入、命中集合由 `workspace.findFiles` 喂入），三者都不碰 DOM 和 `vscode`，由 `src/test/fileReference.test.ts`、`src/test/fileReveal.test.ts` 直接覆盖。`src/test/fileReferenceResolve.test.ts` 覆盖「根目录命中优先、同名多份不认、带目录不回退搜索」。`node test/check-file-reference-dom.mjs`（**71 项**）会把 `chat.js` 里真实的渲染段落切出来、配最小 DOM 跑一遍点击与右键菜单——判定逻辑可以单测，「右键真的发出 `revealFile` / `revealFileInExplorer`」「两项各发各的、不会互相误发」「判不出来的引用会还原成原文」「核实到另一个文件后点击目标一起换」只能这样验。

**流式渲染拆成两个纯函数模块**，因为它们决定的都是「这一帧要不要动 DOM」，属于容易回退、但只能靠跑起来才看得出的性质：

- `media/inline-append.js`（`canAppendPlainText`）：这一小段新增文字能不能直接贴到段落末尾的文本节点上。判定刻意保守——出现反引号 / 星号 / 方括号 / 竖线 / 冒号 / 斜杠 / 换行、像扩展名的 `.xx`、或跨帧能拼成路径（`app` + `.tsx`）一律退回复排。走原地追加时，段落里已有的节点（文件标签、`<strong>` 等）连同悬停状态和过渡动画都不重建，所以鼠标停在已输出的文字上继续流式也不会跳。单测在 `src/test/inlineAppend.test.ts`。
- `media/stream-repair.js`（`repairStreamingMarkdown` / `needsRepair`）：把**尾部还没写完的那一段** markdown 补全再渲染（依据 Vercel Streamdown 的 `remend` 做法）——`**重点` → `**重点**`、`**重点*`（收尾符只写一半）只补 1 个、`` `npm test `` → 补反引号、`[文字](htt` → 换成安全锚点 `#` 让文字立刻收敛成链接文字。星号按**配对扫描**而不是数奇偶；单个 `~` 是字面量（`20~25` 不会被补成删除线）；围栏代码块里不补；只补尾部，前面已完成的段落一个字符都不动。`needsRepair()` 给渲染侧用：尾部仍需补全时禁止原地追加，否则 `**重` 会被当纯文字贴死、等收尾符到了才跳变。单测在 `src/test/streamRepair.test.ts`。
- 消息区在 CSS 里显式 `overflow-anchor: none`：滚动位置每帧由 HWChat 按 `autoFollow` 决定，浏览器再补偿一次就会互相打架（MDN《scroll anchoring》里明确：只有自己接管滚动时才需要关掉它）。

## 主要配置

- `hwchat.apiProfiles` / `hwchat.activeApiProfileId`：OpenAI 兼容接口配置档和当前配置档。
- `hwchat.baseUrl` / `hwchat.model`：兼容旧版配置，并保存当前默认接口和模型。
- `hwchat.defaultMode` / `hwchat.agentMaxSteps`：默认模式和单轮工具循环预算。预算**默认 24 步、绝对上限 200 步**；`0`（旧的「不限制」）和非法值一律回落到默认值，所以历史会话里存着的旧值无法绕过上限。预算用尽时 Agent 会停止调用工具、保留全部已有结果，并提示回复「继续」接着执行。**这两项只作为新对话的初始值**，对话开始后以该对话自己的存档为准（工具条上的改动写回对话，不改全局）。
- `hwchat.searchExclude`：在默认排除列表（`.git`、`node_modules`、`dist`、`build`、`out`、`coverage`、`.next`、`.turbo`、`.venv`、`venv`、`__pycache__`、`DerivedData`、`.cache`）之外，额外不参与工作区搜索的目录名。搜索同时只跑一个，相同参数的并发搜索会合并，结果缓存约 1.5 秒并在每次写入/保存/删除后立即失效；命令单独并发上限为 2，遇到 `EAGAIN` 一类资源错误后 5 秒内降为串行。技能清单不再跟着每次状态重发扫描（30 秒新鲜窗口 + 并发合并，文件变化由 watcher 强制刷新），命令输出按字节有界累积（截断后不再随输出增长重复编码），启动时历史读取也只做一遍。排查资源占用时可用命令 `HWChat: 显示资源统计` 查看实时的搜索与命令计数。
- `hwchat.reasoningEffort`：默认、无、低、高、最大五档思考层级；不支持该参数的兼容接口会自动降级重试。同样只作为新对话的默认值。
- `hwchat.permissionPreset` / `hwchat.agentMaxSteps` / `hwchat.reasoningEffort`：**已废弃，不再生效**。每一条新对话固定从「每次询问 / 24 步 / 默认（模型官方）」开始，这三项在输入框下方的工具条里按对话调整（24 / 68 / 120 / 不限制；默认 / 无 / 模型自己声明的档位；四档权限预设），选择随该对话存档。保留这三个配置键只为让旧的 `settings.json` 不报「未知配置项」。
- `hwchat.fileReadPolicy` / `hwchat.fileWritePolicy` / `hwchat.commandPolicy` / `hwchat.dangerousCommandPolicy` / `hwchat.sensitiveFilePolicy`：这五项策略完全由预设推导，只用于设置页展示，手动写入不生效（在 VS Code 设置里已标记为弃用）。
- 权限类配置是 `resource` 作用域，可以写在某个根目录的 `.vscode/settings.json` 里。生效顺序为「最具体优先」：工作区文件夹 → `.code-workspace` → 用户设置；多个文件夹写了不同值时取最严格的一个（预设严格度 `每次询问` > `风险操作询问` > `Autopilot` > `完全访问`）。
- `hwchat.allowSensitiveFiles` / `hwchat.allowDangerousCommands`：已废弃的旧布尔开关，仅在未设置上面两项新配置时用作迁移回退。
- `hwchat.taskCacheRetentionHours` / `hwchat.cacheBudgetMB`：任务缓存瘦身与**磁盘占用提示**。**HWChat 不会自己让任何一条对话消失**：自动清理只按 `taskCacheRetentionHours` 瘦身缓存、整理「一条消息都没有」的空对话；`historyRetentionDays` 与 `cacheBudgetMB` 不再触发任何删除，预算超了只弹提示并给「打开设置」按钮。删除对话 = 移入 `history-v1/trash/`（可用命令 `HWChat: 恢复已删除的对话` 或设置里的按钮恢复）；**只有你能销毁内容** —— 设置 → 存储 →「清空回收站（永久）」或「清除本地数据」。回收站没有按时间/条数的自动清理。

对话数据位于 VS Code 的全局存储目录，不会写入项目目录。归档会在对话目录里写一份 `.archived` 标记，所以 `manifest.json` 损坏或过期（包括回退读取的 `manifest.json.bak`——那是**上一次**写盘的内容）都不会把归档对话变回可删除的普通历史。
