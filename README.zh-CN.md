# HWChat

[English](README.md) · 中文

当前版本：**0.2.1**

HWChat 是面向 VS Code 的本地优先编码 Agent 扩展。项目仓库：<https://github.com/Gsaecy/DeepSeek-HWChat>

HWChat 是一个在 VS Code 内直接编码的 DeepSeek / OpenAI 兼容 Agent 扩展。它提供简洁的聊天与设置界面、原生流式 tool calling、本地 Skill、文件附件、权限预设、归档历史和可恢复的分片存储。聊天固定在 VS Code 右侧辅助侧边栏，不会再占用编辑器标签页。

![HWChat 聊天面板：左侧会话列表与新建对话](https://raw.githubusercontent.com/Gsaecy/DeepSeek-HWChat/main/docs/screenshots/chat-panel.png)

延伸阅读：[HWChat 推荐文章](docs/article-zh.md)（约 3500 字，讲设计取舍：为什么解绑模型、四档权限怎么划、Skill 为什么要路由加载）。

## 编码 Agent

- `Agent`：读取和搜索项目、检查诊断、创建/修改/移动/删除文件、运行命令，并把工具结果继续回传模型完成多轮任务。
- `Plan`：只开放只读工具，用于分析代码和制定方案，不修改工作区。
- `Chat`：不开放工作区工具，仅使用对话和明确添加的上下文。
- 工作模式以「对话工具条的下拉」和「设置里的默认模式」为准：新对话用 `hwchat.defaultMode`，在工具条里切换会立刻写进当前对话存档，之后每次请求都按它执行；每次请求还会把当前模式明确写进系统提示词（并声明以本轮为准），所以跨模式续聊不会沿用上一个模式的假设。工具清单、权限拦截和提示词三处用的是同一个模式值。
- 原生识别 VS Code 的单根和多根工作区，可直接列出工作区根目录、浏览目录、读取文件，并通过 `open_file` 在编辑器中打开文件，不再绕行终端、`code` CLI 或其它扩展工具。由 VS Code 扩展提供的桥接工具与原生工具受同一套路径隔离约束，其说明里会标注文件类参数必须使用工作区内绝对路径。
- 在受信任工作区和当前权限预设允许时，Agent 可自行执行工作区内命令。终端命令按风险分成三档：只读命令（`ls`、`git status`、`grep` 等）、正常命令（安装、构建、提交等）和危险命令（提权、破坏性删除、磁盘擦写、强制推送、把网络脚本管道给 shell 等）。`每次询问` 全部确认且危险命令直接拒绝；`风险操作询问` / `Autopilot` 自动执行只读与正常命令、危险命令逐次确认；`完全访问` 连危险命令也自动执行，但读取敏感文件时仍逐次确认。未受信任工作区和工作区外路径隔离始终有效。命令里 `sed` / `grep` 的模式或脚本参数（如 `sed -n '/a/,/^b/p'`）按模式处理，不会被误判成越界路径；真正的文件参数仍然逐个校验，直接指向文件系统根的写法（如 `rm -rf /`）同样会被拒绝。
- 每个执行步骤默认折叠，只显示结果摘要；展开后可查看工具输入、输出、审批状态、耗时和涉及文件。展开/收起状态由用户决定：流式输出期间列表重新渲染也不会再自动收起，点开保持展开，再点一次才收起。
- 可从聊天输入区添加多个文件，也可在资源管理器右键选择“HWChat: 添加文件到对话”。文件内容不会发送给 Webview，只在扩展宿主中按需加入 API 请求。
- 支持多个 OpenAI 兼容 API 配置档，每个配置档可独立保存地址、API Key、模型列表和请求头，并在对话标题下方的控件行即时切换。
- 模型选择不依赖 Copilot 或其它扩展注册的模型。HWChat 会直接调用当前 API 的 `/models` 接口读取可用细分模型和展示名称，过滤接口标记为停用、过期或不可用的模型，并记住用户手动排除的模型；DeepSeek 官网接口在首次刷新前以 `deepseek-flash` 和 `deepseek-v4-pro` 作为离线兜底。
- 思考深度跟随当前模型能力：仅当 `/models` 元数据声明支持多档调节时开放选择；不支持、固定思考或能力未知的模型不会伪装成可调节。兼容接口拒绝思考参数时会自动移除不支持的参数后重试。
- 每条完成的助手回复显示本轮 Token 消耗，统一换算为百万 Token（`M tokens`）；左侧对话记录显示该对话所有轮次的累计消耗。
- 对话面板顶部第一行只放对话标题与状态，第二行单独放工作模式、API 配置、模型、刷新，以及靠右的 Skill、归档、导出、设置控件（Skill 在设置左侧）；面板变窄时控件自动换行而不是压缩标题。
- 输入框是单个圆角框：上方是文本输入区，框内底部单独一行放权限预设、最大步骤、思考层级，以及靠右的附件、语音、发送/停止按钮（附件在语音左侧）。这一行在任何宽度都保持单行不换行；变窄时按「思考深度 → 最大步骤 → 权限预设」的顺序隐藏文字前缀，只保留当前选中的选项。执行步骤默认不限；切换权限预设时会显示对应档位的风险说明，确认后对下一次发送立即生效。
- Agent 运行时输入框仍可编辑和发送。相关补充会合并到当前任务并在下一个工具边界重新规划，尚未执行的冲突步骤会跳过；无关任务进入可见任务树队列，前一分支完成后自动继续。
- 运行中插入的每个问题都会立即生成自己的排队回答位，并最终把结果显示在对应问题下方，不再把后续问题的答案堆到上一条回复前面。
- Agent 运行时可以自由向上查看历史；只有用户停留在底部时才自动跟随流式输出。执行期间输入框里的发送按钮会换成**红色高亮的停止按钮**（危险色底 + 呼吸光环，图标为实心方块），一眼能看出任务正在跑、点这里可以停；系统开启“减少动态效果”时不播放动画。
- 支持从输入框粘贴图片、截图和文件，粘贴后会先显示本地缩略图。图片会以兼容 OpenAI 的多模态内容发送；任务缓存到期后会移除附件正文、图片 Base64 和缩略图，只保留名称、类型和大小摘要。
- 支持语音输入。HWChat 仅接收识别后的文字，不把音频写入对话缓存；识别文字仍需点击发送才会提交给当前 API。
- 模型回复会按 Markdown 结构排版，而不是一整段纯文本：标题（`#` ~ `######`）、有序/无序列表（按缩进嵌套）、表格（含对齐与横向滚动）、引用、分隔线都会被渲染出来，行内支持加粗、`行内代码`、删除线和 `[文字](链接)`。终端命令显示为独立的“终端命令”代码块，并提供经 VS Code 剪贴板确认的一键复制；Agent 执行步骤中的提交内容、返回结果和实际命令也可直接复制，消息正文支持选择后用 `⌘/Ctrl+C` 复制。执行步骤汇总用“处理过程 · 共 N 步，改动 M 个文件”这类说法，尽量让不写代码的读者也能读。回复里的每段“我打算做什么”后面会紧跟它触发的那组步骤（做了什么、结果如何），说明与步骤按发生顺序交错出现，不用再上下对照；一组只有一步时不显示汇总标题，历史消息（旧数据）仍按“步骤汇总 + 正文”显示。
- 输入框支持 `⌘/Ctrl+V` 粘贴文字、图片、截图和文件；剪贴板同时包含文字和附件时会一起保留，并在 Webview 原生粘贴失效时自动使用 VS Code 剪贴板兜底。
- 除内置工作区工具外，HWChat 会发现并调用当前 VS Code 中通过 Language Model Tool API 暴露的全部扩展工具（不再固定截断在 100 个）；需要授权的工具只弹 VS Code 自己的确认框，不需要授权的工具直接调用，HWChat 不再叠加一层“允许 Agent …”弹窗。启动时会激活声明了语言模型工具但尚未运行的扩展，模型调用了暂时缺失的工具时也会补激活一次再重试；网页、文本、Markdown 和差异内容可直接在编辑区预览。
- 可从任意历史记录点击“续接”，或运行命令 `HWChat: 在新对话中续接当前任务历史`。新对话保存来源对话的本地只读交接摘要，Agent 还可按需检索来源链中的旧消息，避免重复踩已经记录的坑。旧对话不会被复制或修改；本地保存本身不产生 API Token，但实际发送给模型的摘要和检索片段会计入输入 Token。

## 任务清单

任务需要拆成多步时，Agent 会写一份任务清单，而不是让你从正文里推断进度。清单位于任务树和输入框之间，按执行顺序编号：左边是这一步要做什么，右边是它的状态。

| 状态 | 显示 |
| --- | --- |
| 等待执行 | 绿色空心圆圈 |
| 执行中 | 绿色跳动的省略号 |
| 已完成 | 实心绿色圆圈 + 白色对勾 |

点标题即可收起或展开，和任务树一样。Agent 始终只让一项处于执行中，每完成一步就更新一次清单，全部做完后保留整份清单作为记录。清单随对话保存，重载窗口后仍在；只有一步的任务不会创建清单。它是一个不需要授权的工具（`update_todos`），因为既不读也不写工作区文件、不执行命令。

### 归档胶囊

一份清单**全部完成**后，运行结束时会自动归档：清单从输入框上方收走，「任务清单」折叠框消失，位置换成输入框上方一颗左对齐的纯色胶囊。

- 点胶囊展开那份历史清单（标题写「已归档任务清单」，汇总带归档时间，边框改虚线），再点一次收起。
- 一份对话可以有多份归档，新的排在上一个的右边；颜色按「越新越蓝」渐变——绿 `#2ea043` → 浅蓝 `#4aa8e0` → 深蓝 `#1e4fd8`，每颗单色。
- 胶囊**永不换行**，宽高比恒为 **3:1**，初始高 16px（宽 48px）。胶囊变多或面板变窄时宽高一起缩小（缩到 6px 高为止），缩小后自动隐藏内部图标只留纯色形状。
- 一份对话最多保留 12 份归档，超出丢弃最早的一份。中途被停止或失败、仍有未完成项的清单**不会**归档，见下方「中断的清单」。
- 归档随对话落库（manifest 的 `todoArchives`），重载窗口后仍在；磁盘上的脏数据在读入时会被丢弃，不影响对话本身。

### 中断的清单

停止、报错、关窗口（或进程被杀）都会让一份清单停在半路。这类清单按保守方式处理，不会变成胶囊：

- 清单**原样留在面板上**，「执行中」那一项降级成**等待执行**（绿色空心圆圈），不再播跳动动画——没人推进它时不该假装还在跑；折叠框标题上会补一句「已中断，可继续」。
- **接着做**：让 Agent 继续这份任务，它会沿用原清单、把当前项改回执行中，全部完成后照常归档成胶囊。
- **换新任务**：直接提新需求即可，模型给出的新清单会**整体覆盖**旧清单——旧的那份不保留，也不会进归档。

中断标记随对话落库（manifest 的 `todosInterrupted`）；老存档没有这个字段，载入时按「未中断」处理。

## 并发对话

每个对话各自跑自己的 Agent 线程，互不阻塞：

- 对话进行中可以直接点「新建对话」或别的历史记录，被切走的那条继续在后台跑，历史列表上用蓝点标出「运行中」。
- 停止按钮只停当前显示的那条线程；归档、删除也只拦同一条对话。
- 模型 / 模式 / 技能 / 权限预设只在这条对话自己忙时禁用，不会因为别的对话在跑就整块锁死。
- 后台线程结束只刷新历史列表，不打断当前正在读的对话的滚动位置。

## Skills

HWChat 扫描以下本地格式：

- `.hwchat/skills/*.md`
- `.agents/skills/**/SKILL.md`
- `.claude/skills/**/SKILL.md`
- VS Code 全局存储中的用户 Skill 目录
- `~/.copilot/skills/**/SKILL.md`

HWChat 与“本地skill快捷调用”共享 `~/.copilot/.skill-quick-launch.json`。在那里勾选的 Skill 会成为新对话的默认选择，但“默认启用”不等于每轮都加载：`route` 模式下，Agent / Plan 会先看到轻量路由表，仅在任务匹配时通过 `load_skill` 读取全文；Chat 模式会按任务文字匹配后预载。每条回复只显示本轮真正读取过的 Skill 名称和数量，并把最近调用时间同步回快捷调用扩展。

用户也可以在当前对话中手动增减 Skill。非快捷调用来源的已选 Skill，以及 `always` 模式下的 Skill，会直接加入本轮系统上下文。支持简单 YAML frontmatter 的 `name` 和 `description`。

## 界面语言

设置页「通用 → 界面语言」可在中文与 English 之间切换，也可设为「自动」跟随 VS Code 的显示语言。切换后对话面板、设置页、通知和错误提示会立即换成对应语言，不需要重载窗口。命令面板里的命令标题与设置项说明跟随 VS Code 自身的显示语言（扩展的 NLS 机制）。

## 权限与隐私

- API Key 使用 VS Code `SecretStorage`，不会写入项目或对话记录。
- 首次发送前明确展示数据流向并取得同意。
- 提供“每次询问 / 风险操作询问 / Autopilot / 完全访问”四档权限预设（不提供逐项自定义组合），设置页内置各档位边界对照表，输入框下拉项也带同源说明：

| 档位 | 读取 | 写入 | 只读命令 | 正常命令 | 危险命令 | 敏感文件 |
| --- | --- | --- | --- | --- | --- | --- |
| 每次询问 | 逐次确认 | 逐次确认 | 逐次确认 | 逐次确认 | 直接拒绝 | 禁止 |
| 风险操作询问 | 自动允许 | 自动允许（工作区内） | 自动允许 | 自动允许 | 逐次确认 | 禁止 |
| Autopilot | 自动允许 | 自动允许（工作区内） | 自动允许 | 自动允许 | 自动允许 | 禁止 |
| 完全访问 | 自动允许 | 自动允许（工作区内） | 自动允许 | 自动允许 | 自动允许 | 逐次确认 |

- 只读命令是 `ls`、`git status`、`grep` 等无副作用命令；正常命令是安装、构建、提交等常规命令；危险命令是提权、破坏性删除、磁盘擦写、强制推送、把网络脚本管道给 shell 等操作。
- 未受信任工作区中的写入和命令始终关闭。
- `.env`、证书、私钥、SSH/AWS/Kubernetes 凭据路径按“敏感文件”策略处理：默认禁止，设为“逐次确认”时每次访问都会弹窗说明目标文件，设为“允许”才自动读取。
- 工具授权在**对话面板内**给出（输入框上方一张卡片：拒绝 / 允许一次 + 可折叠详情），不使用会锁住整个 VS Code 窗口的模态对话框，等待授权时仍可拖动分栏、切换对话、编辑文件。若该对话在后台等待授权，历史列表会用黄点标出「等待授权」，切回去即可处理；任务被停止或结束时授权请求立即作废。
- 子进程环境会移除常见 Token、Secret、Password 和 API Key 变量。
- 远程 API 地址必须使用 HTTPS；只有本机 `localhost`、`127.0.0.1` 和 `::1` 可使用 HTTP。
- 无遥测。对话、Skill 和 Agent 审计记录默认只保存在本机，可在设置中全部删除。

详细边界见 [SECURITY.md](SECURITY.md)。

## 历史与缓存

- 每条消息独立存储，采用同目录临时文件、原子替换和恢复备份，索引损坏时会从磁盘重建。
- 流式回复每 1.5 秒持久化；扩展异常退出后保留已经生成的内容。
- 对话支持固定、归档、恢复、搜索、删除和流式导出。
- 被续接对话引用的来源历史会受自动清理保护；手动删除来源前会提示其对后续按需检索的影响。续接对话仍保留创建时的本地摘要。
- 已完成任务的思考过程、Token 输入/输出明细、工具输入/输出和附件正文会按保留时间自动瘦身，但最终回复、累计 Token、实际调用的 Skill、工具摘要、文件列表和审批结果会保留。
- UI 和模型上下文都有条数与字节上限；附件还有单文件、数量和总容量限制。
- 超出磁盘预算时按最久未使用顺序淘汰普通对话，固定、归档和执行中的对话不会被删除。

## 开发

运行要求：VS Code `1.106.0` 或更高版本，Node.js 20+。

安装已构建的 VSIX：

```bash
code --install-extension hwchat-0.2.1.vsix
```

在 VS Code 中打开命令面板，执行 `HWChat: 打开对话面板`。首次使用时进入设置，创建一个 API 配置档并保存 API Key；密钥只会进入 VS Code SecretStorage，不会写入 `settings.json`、项目文件或 VSIX。

从源码构建：

```bash
npm install
npm run check
npm test
npm run package
```

构建结果为项目根目录下的 `hwchat-0.2.1.vsix`。同一扩展已发布过的版本不能覆盖上传 Marketplace，发布新构建时必须递增版本号。

扩展图标使用 `resources/logo.png`。在 VS Code 中按 `F5` 启动扩展开发主机。

## 主要配置

- `hwchat.apiProfiles` / `hwchat.activeApiProfileId`：OpenAI 兼容接口配置档和当前配置档。
- `hwchat.baseUrl` / `hwchat.model`：兼容旧版配置，并保存当前默认接口和模型。
- `hwchat.defaultMode` / `hwchat.agentMaxSteps`：默认模式和单轮工具循环上限；步骤为 `0` 时不限制。默认模式只决定新对话的初始模式，之后在对话工具条里切换以对话存档为准。
- `hwchat.reasoningEffort`：默认、无、低、高、最大五档思考层级；不支持该参数的兼容接口会自动降级重试。
- `hwchat.permissionPreset`：常用权限预设（每次询问 / 风险操作询问 / Autopilot / 完全访问），四档之一。
- `hwchat.fileReadPolicy` / `hwchat.fileWritePolicy` / `hwchat.commandPolicy` / `hwchat.dangerousCommandPolicy` / `hwchat.sensitiveFilePolicy`：这五项策略完全由预设推导，只用于设置页展示，手动写入不生效（在 VS Code 设置里已标记为弃用）。
- 权限类配置是 `resource` 作用域，可以写在某个根目录的 `.vscode/settings.json` 里。生效顺序为「最具体优先」：工作区文件夹 → `.code-workspace` → 用户设置；多个文件夹写了不同值时取最严格的一个（预设严格度 `每次询问` > `风险操作询问` > `Autopilot` > `完全访问`）。
- `hwchat.allowSensitiveFiles` / `hwchat.allowDangerousCommands`：已废弃的旧布尔开关，仅在未设置上面两项新配置时用作迁移回退。
- `hwchat.taskCacheRetentionHours` / `hwchat.cacheBudgetMB`：任务缓存和磁盘预算。

对话数据位于 VS Code 的全局存储目录，不会写入项目目录。
